Wikialisa — Báo Cáo Nhận Xét IP Lõi

Phân tích từ góc nhìn đa vai trò dựa trên đọc toàn bộ mã nguồn Monorepo

Phạm vi: 11 apps · 14 packages · 9 services · 5 smart contract programs Stack: Solana Anchor (Rust) · EVM Solidity · Node.js/TypeScript · Next.js 14 Ngày phân tích: Tháng 7 / 2025

Wikialisa được thiết kế như một IP lõi (core intellectual property) cho toàn hệ sinh thái tập đoàn AXQ TECH HOLDING — từ tầng L1/L2 blockchain (SVM + ZK), đến SWIFT institutional bridge, P2P escrow, AMM DEX, DAO governance, và wallet UX. Mã nguồn thực tế đã triển khai được (~60%) với chất lượng kiến trúc tốt ở tầng protocol/smart contract, nhưng tầng ứng dụng đang ở trạng thái MVP với nhiều rủi ro cần giải quyết trước khi ra sản phẩm. Báo cáo dưới đây phân tích từng vai trò.

  • TỐT Cấu trúc pháp nhân 8 công ty thành viên (VN + SG + Cayman + Dubai) ánh xạ trực tiếp 1:1 lên 11 subdomain và module kỹ thuật — kiến trúc tập đoàn có tư duy rất hệ thống.

Vai trò 3 — Smart Contract Engineer

Nhìn từ góc độ correctness, security, và on-chain logic của 5 programs

Phân tích từng program
  • AN TOÀN AXVN-p2p-escrow (Anchor/Rust): PDA seeds chuẩn [b"order_state", order_id], vault PDA [b"escrow_vault", order_id], signer bump đúng. CpiContext::new_with_signer dùng order_state làm authority → không thể drain vault không qua instruction. OrderStatus enum đầy đủ 6 trạng thái. Events emit đầy đủ.
  • AN TOÀN AXVN-mint-governance (Anchor/Rust): max_supply cap checked với checked_add (overflow safe). Whitelist gate trước mỗi mint. GovernanceConfig.authority constraint kiểm tra mọi admin action. Burn dùng saturating_sub (không panic khi supply underflow).
  • AN TOÀN VNKRSwiftBridgeV2.sol (EVM/Solidity): Two-step relayer change (proposeRelayer + acceptRelayer) — pattern đúng. UETR idempotency bằng keccak256 hash → replay-proof. Fee cap cứng maxBps=500 (5%). Treasury vault nhận fee thay vì fee recipient tùy ý — đúng.
  • LƯU Ý AXVN-swift-bridge/solana: Dùng Program ID placeholder SWFTb111... — chưa deploy. Cần IDL generation và test suite Anchor trước khi deploy devnet.
Rủi ro & Điểm cần cải thiện
  • CẦN FIX AXVNSwiftBridgeV2.sol: hàm settleInboundSwiftWithFX() tính grossAxvn = originalAmount × fxRate × 1e18 — overflow risk khi originalAmount lớn (e.g. $100M = 10^8) × fxRate USD/VND (25450) × 1e18 = 2.5×10^30, vượt uint256 max (1.15×10^77) nên an toàn, nhưng nên dùng SafeMath library hoặc checked arithmetic để documentation rõ ràng.
  • THIẾU AXVN-amm-swap và AXVN-treasury-rbs: cả 2 programs được liệt kê trong README nhưng chỉ có thư mục trống — không có src/lib.rs. Đây là 2 program quan trọng nhất về kinh tế (liquidity + stability).
  • BẮT BUỘC Toàn bộ 5 programs chưa có audit từ bên thứ ba. Trước khi mainnet TGE phải có ít nhất 1 firm audit (OtterSec / Halborn / Trail of Bits) + Bug Bounty.
  • CẦN P2P escrow: thiếu dispute resolution mechanism. OrderStatus::Disputed được định nghĩa nhưng không có instruction nào xử lý dispute. Cần arbitrator PDA hoặc DAO vote mechanism.
Nhận định Smart Contract Engineer: Các programs đã implement (P2P escrow, Mint governance, SWIFT Bridge V2) đều viết theo đúng pattern Anchor/Solidity. Logic on-chain sound, không có reentrancy hay integer overflow rõ ràng. Priority: (1) implement AXVN-amm-swap + treasury-rbs, (2) viết test suite Anchor, (3) security audit chuyên nghiệp.

Vai trò 6 — Security Auditor / Compliance

Nhìn từ góc độ threat model, attack surface, regulatory compliance (SBV, VARA, MAS)

Attack Surface Analysis
  • CRITICAL Web Storage Token Leakage: Access token + refresh token + PIN lưu localStorage. Một XSS attack đơn giản trên bất kỳ third-party script nào có thể drain toàn bộ session và bypass PIN. Remediation: httpOnly SameSite=Strict cookies + server-side PIN verification.
  • CRITICAL Admin Portal Unauthenticated: /admin/dashboard không có role check — toàn bộ KYC decisions, user lock/suspend, compliance reports, withdrawal approvals accessible without auth. Remediation: middleware.ts với JWT role claim validation.
  • HIGH SWIFT LAU Key Management: SWIFT_LAU_KEY trong .env plaintext. Production cần HSM hoặc AWS KMS / HashiCorp Vault với key rotation policy.
  • HIGH Oracle Manipulation: FX Oracle fallback về hardcoded rates khi SBV và Vietcombank API đều down — có thể bị exploit trong điều kiện network partition. Cần secondary oracle (Chainlink) hoặc circuit breaker dừng settlement khi không có live rate.
  • MEDIUM UETR Replay Risk: EVM bridge dùng keccak256(uetr) để chặn duplicate — đúng. Solana program cần tương đương on-chain UETR tracking account.
  • MEDIUM BANK_WEBHOOK_SECRET validation: fiat-connector-api có env BANK_WEBHOOK_SECRET nhưng không rõ middleware HMAC validation đã implement chưa — nếu thiếu, bất kỳ HTTP request nào cũng có thể giả webhook ngân hàng và trigger P2P release.
Regulatory Compliance Gap
  • CẦN NĐ-284/2025 (Việt Nam): eKYC liveness detection dùng setTimeout fake — không đạt yêu cầu xác thực biometric theo quy định NHNN. Cần SDK đạt ISO 30107 PAD level 2.
  • CẦN AML/CFT: AMLVerifyRequest type đã được define trong types package nhưng không có service nào implement AML scoring thực sự. Admin compliance page có AML flags UI nhưng không có action workflow.
  • CẦN VARA (Dubai): OTC engine (otc.axvn.vn) được giao cho AXQ Labs MENA nhưng không có code implementation và VARA compliance gateway chưa rõ.
  • LƯU Ý MAS (Singapore): swap.axvn.vn (AMM DEX) phục vụ thị trường quốc tế qua AXQ Global Ventures Pte.Ltd. Cần Payment Services Act license hoặc exemption letter từ MAS trước khi go-live.
Điểm bảo mật tốt
  • TỐT EVM bridge: two-step relayer handover (propose + accept) — đúng pattern, tránh admin mistake khi rotate key.
  • TỐT Solana programs: PDA-based vault, bump stored in state, no raw PublicKey as authority — theo đúng Anchor security guidelines.
  • TỐT .npmrc có NTM (Node Trust Manager) security config để kiểm tra checksum packages — supply chain security tốt.
  • TỐT SWIFT_MGW_URL internal (:9003) không exposed ra ngoài — sidecar pattern đúng.
Nhận định Security Auditor: Hệ thống không sẵn sàng cho production từ góc độ bảo mật. Hai rủi ro catastrophic cần fix ngay: (1) toàn bộ authentication token storage, (2) admin portal không có auth. Sau đó cần penetration test focused vào SWIFT webhook validation và oracle manipulation before mainnet.
